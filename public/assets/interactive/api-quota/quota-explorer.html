¿Qué solicitudes admite el token bucket?

Modelo con reloj controlado y el mismo algoritmo de cuota del laboratorio. Cada intento cuesta un token. No hace peticiones a una API ni mide tráfico, rendimiento o dinero. No simula el límite de trabajos activos.

Saldo observado de North

La posición horizontal cuenta intentos de North, no segundos. Cada punto muestra su saldo después de decidir. El saldo se actualiza al consultar el bucket.

Decisiones con tiempo controlado

    Un rechazo no gasta un token adicional y cada tenant tiene su bucket. Retry-After es orientativo: una nueva solicitud puede llegar antes que tu reintento. En el laboratorio HTTP se aplican además cupos de concurrencia; este gráfico no los representa.
